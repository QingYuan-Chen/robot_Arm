# Star Arm 102-LD → reBot B601 Python SDK 方向映射设计

## 目标

构建一个独立、无需 ROS 的 Python 工具，读取 Star Arm 102-LD 引导臂和
reBot B601-DM 从臂，并以从臂的坐标约定为基准，验证各关节的方向映射。

第一个里程碑仅执行只读操作。工具不得使能、失能、置零、切换模式或向任一机械臂
发送控制指令。真机主从跟随属于后续独立里程碑，开始前必须重新评审设计并获得明确
的真机运动授权。

## 已验证的硬件基线

- 引导臂：`/dev/ttyUSB0`，CH340 串口，FashionStar 舵机 ID `0..6`，
  波特率 `1_000_000`。
- 从臂：`/dev/ttyACM0`，达妙串口桥，机械臂电机 ID `0x01..0x06`，
  夹爪 ID `0x07`。
- 现有 ROS 控制器被确认处于失能、空闲状态，六个机械臂电机均为
  `status_code=0`；随后在纯 Python 探测前正常停止了该控制器。
- 纯 Python `motorbridge` 反馈探测对六个关节和夹爪均取得 20/20 次有效采样，
  所有电机均为 `status_code=0`。
- FashionStar 仅监视探测对引导臂 ID `0..6` 均取得 12/12 次有效采样。

上述探测仅使用 FashionStar 监视查询码 22 和达妙反馈请求，没有调用任何运动或配置方法。

## 方案比较

### 1. 直接使用两个 SDK 读取器（采用）

引导臂使用 `fashionstar_uart_sdk`，从臂使用 `motorbridge`。该方案符合 Python 优先、
暂不使用 ROS 的要求，并且每一次读取操作都可审计。其代价是后续真机跟随需要显式设计
安全控制器，不能直接复用 ROS 动作接口所提供的控制流程。

### 2. Python 引导臂读取器配合 ROS 从臂接口

该方案可以复用现有 reBot 控制器的安全边界，但它不是无需 ROS 的 Python SDK 测试，
而且当前任务已明确将 ROS 2 延后。

### 3. LeRobot 主从集成

上游 LeRobot 配对方案可以较快实现真机遥操作，但其连接和标定生命周期可能使能硬件或
重新置零。对于首个方向映射里程碑，该方案范围过大，也更难证明整个探测过程严格只读。

## 坐标基准与候选映射

从臂的关节顺序和单位是唯一基准：

| 引导臂舵机 | 从臂关节 | 候选符号 | 单位换算 |
| --- | --- | ---: | --- |
| ID 0 | `joint1` | `-1` | 度 → 弧度 |
| ID 1 | `joint2` | `-1` | 度 → 弧度 |
| ID 2 | `joint3` | `+1` | 度 → 弧度 |
| ID 3 | `joint4` | `+1` | 度 → 弧度 |
| ID 4 | `joint5` | `+1` | 度 → 弧度 |
| ID 5 | `joint6` | `-1` | 度 → 弧度 |
| ID 6 | `gripper` | 未验证 | 单独标定行程 |

机械臂映射必须基于采集到的相对基线，绝不能直接复制绝对角度：

```text
q_virtual_follower[i] = q_follower_baseline[i]
                        + sign[i] * scale[i]
                        * radians(q_leader[i] - q_leader_baseline[i])
```

J1～J6 的初始比例系数均为 `1.0`。程序会报告实测比例证据，但不会在未确认的情况下
自动替换配置中的比例系数。夹爪不纳入机械臂方向验收：引导臂输出的是旋转手柄角度，
而当前从臂 API 最终提供的是夹爪开合行程，两者需要单独测量端点并完成映射。

## 组件划分

所有新增代码均放在这个独立检出目录的 `Python_SDK/rebot_b601_mapping/` 下。

- `models.py`：不可变采样、关节规格、基线和结果记录。
- `leader_reader.py`：独占串口，并以仅监视方式读取 ID `0..6`。该模块不得暴露
  重置、停止模式、设置原点或写入目标值的方法。
- `follower_reader.py`：创建达妙控制器、注册电机、调用 `request_feedback()`、轮询并
  读取状态。该模块不得暴露使能、失能、置零、模式切换或控制指令方法。
- `mapping.py`：单位换算、相对基线映射、新鲜度检查、关节隔离检查、符号推断和
  验收状态管理。
- `cli.py`：提供 `snapshot` 和 `calibrate-directions` 命令，要求显式传入串口参数，
  并输出易读表格和 JSON 证据。
- `mapping.example.json`：保存候选符号、限制、阈值，以及每个关节明确的
  `verified: false` 初始状态。
- `tests/`：使用伪读取器、无需硬件的单元测试，以及默认不会作为普通单元测试收集的
  可选真机冒烟测试。

上游 `stararm102_ro.py` 保持不变且不执行，因为它的启动路径会解锁引导臂并重置多圈角度。

## 只读工作流程

1. 如果任一串口已被占用，则拒绝启动。
2. 独占打开引导臂串口，并打开从臂串口桥；整个过程不发送模式或生命周期指令。
3. 连续读取两台机械臂的多个样本，并要求从臂全部七个电机均报告
   `status_code=0`。
4. 采集稳定样本的中位数作为基线。若数据缺失、过期、不是有限数值，或运动速度超过
   配置的稳定性阈值，则拒绝采集基线。
5. 在 `snapshot` 模式下，输出原始值、换算值、候选映射得到的虚拟从臂目标值以及
   JSON 证据，但绝不把任何方向标记为已验证。
6. 在 `calibrate-directions` 模式下，每次只处理一个明确选定的关节。操作员仅手动移动
   指定关节，并按需要托住机械臂。如果其他关节出现明显运动，则拒绝该组样本。
7. 根据引导臂与从臂的角度增量推断候选符号。只有运动增量达到最小阈值、采样窗口内
   符号保持一致，并获得操作员确认后，才保存 `verified: true`。
8. 在 `finally` 代码块中关闭两个串口。收到 Ctrl+C 或读取失败时直接退出，不发送任何
   生命周期或运动指令。

## 失败处理策略

出现以下任一情况时，工具必须按安全方式拒绝继续：

- 串口被占用，或串口设备身份发生变化；
- 任一预期的引导臂 ID 或从臂电机缺失；
- 任一从臂状态不为 `0`；
- 样本过期、不是有限数值，或超出配置的从臂关节限制；
- 在方向标定期间，选定关节以外的其他关节发生运动；
- 推断出的符号不一致，或运动幅度过小；
- 通过机械臂方向标定命令请求夹爪标定。

任何失败路径都不得调用失能。该工具严格只读，因此不能假定自己拥有电机生命周期的
控制权。操作员始终掌握物理断电手段，并在手动移动失能机械臂时负责提供必要支撑。

## 测试与验收

### 自动化测试

- 验证 J1～J6 和夹爪的 ID、名称及顺序映射完全一致。
- 验证度到弧度的换算以及相对基线公式。
- 验证候选符号向量 `[-1, -1, +1, +1, +1, -1]`。
- 验证对数据缺失、过期、非有限数值以及状态不为零的情况予以拒绝。
- 验证选定关节隔离检查和符号不一致拒绝逻辑。
- 未获得操作员明确确认时，不得持久化配置。
- 使用伪读取器证明不会调用任何被禁止的生命周期或控制方法。
- 收到 Ctrl+C 或发生异常时，必须关闭两个通信通道。

### 本里程碑的真机验收

- `snapshot` 从两台机械臂各取得至少 20 个连续有效样本。
- 分别检查六个机械臂关节，且未请求的关节不得运动。
- 记录全部六个方向符号、移动前后的原始值以及操作员确认结果。
- 最终证据文件中的夹爪仍保持未验证状态。
- 整个过程中所有从臂状态始终为 `0`，且未发送使能、置零、模式、位置、速度、力矩或
  轨迹指令。

通过该里程碑只能证明数据采集和坐标映射正确，不能据此授权真机跟随运动。
